## Harness changes

- **Harness bug found:** the reduced-motion project set `reducedMotion` as a bare `use` key. Playwright Test ignores that, so the first run **never emulated reduced motion**. Fixed with `contextOptions: { reducedMotion: 'reduce' }`. The spec now fails loudly if the emulation is missing.
- **S06 Prev/Next is stricter.** It goes forward to the last card, presses Next at the end, goes back to the first card, and presses Prev at the start. It then scrolls manually to mid-stack and presses Prev and Next. It checks for blank gaps after every step and records frames.
- **Reduced motion is stricter.** Hero and image parallax are now hard checks. The test flags translation only; the static CSS scale is part of the design.

## Cookie banner overlap: investigation and proposal (not implemented)

Measured after the banner appears (5 s delay), light theme:

| Viewport | Banner height | Covers |
|---|---|---|
| phone-390 | 176 px (21 % of the screen) | Project card "Explore project" link and the P1/03 counter; the DARK/LIGHT switcher sits on top of the banner |
| ipad-1180 | 139 px (17 %) | P1/03 counter; directly under the card's "Explore project" link |
| ipad-1366 / portrait | 12–14 % | Bottom-left HUD |
| Hero (all) | — | Clear at load. The hero text sits above the banner |

**Proposed minimal fix (works for either theme, no redesign):**

1. **Compact layout.** Short text ("We use cookies to improve your visit."), with Accept and Decline on the same row as the text from 768 px up. On the phone: two lines of text plus one button row, target height ≤ 96 px. The fonts, card surface and colours stay the existing tokens, so it follows the theme automatically.
2. **Keep it out of the way of fixed UI.** While the banner is visible, set `html.has-cookies`, which sets `--ui-inset-bottom: <banner height>`. The projects HUD (P1/03, Prev/Next) and the theme switcher are lifted by that inset. When the banner closes, the inset returns to 0. It is one CSS variable and does not change the layout otherwise.
3. **Safe areas.** `bottom: max(12px, env(safe-area-inset-bottom))` so the iPhone home indicator and the iPad dock gesture area never clip the buttons.
4. **Remove the theme switcher** once the theme is chosen; that removes the phone collision entirely. Until then, step 2 stacks the switcher above the banner.

Re-verify by adding an overlap probe to the harness (banner rect ∩ HUD/CTA rects = ∅ at all viewports).
